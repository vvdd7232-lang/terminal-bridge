# Участие в разработке TerminalBridge

Спасибо, что заглянули. Проект небольшой, поэтому правил немного — но они
экономит время всем.

## Что где лежит

| Путь | Что это |
|---|---|
| `extension/` | MV3-расширение: `background.js` (Service Worker), `content.js` (точка входа content-script), `ax-*.js` (детектор блоков, панель, палитра, вставка результата, ядро), `options.*` / `popup.*` — страницы настроек и меню |
| `server/` | Локальный сервер на стандартной библиотеке Python: `server.py` (HTTP API, запуск команд, whitelist, токен), `mcp_client.py` (MCP-клиент), `mcp_servers.json` (шаблон конфигурации) |
| `tests/` | `*.test.js` — тесты расширения на jsdom, `test_*.py` — тесты сервера через `unittest` |
| `tools/` | Сборка релиза, публикация, проверка версий, скриншоты, smoke-проверки ([подробнее](tools/README.md)) |
| `docs/` | Заметки о релизах и документация по MCP-серверам |
| `SYSTEM_PROMPT.md` | Промпт, который пользователь копирует в чат с ИИ |

## Окружение

- **Python 3.8+** — для сервера; сторонних зависимостей нет, только стандартная библиотека.
- **Node 20+** — только чтобы гонять тесты расширения.

```bash
# JS-тесты расширения
cd tests && npm ci && npm test

# Тесты сервера
python3 -m unittest discover -s tests -v

# Всё сразу + проверка согласованности версий
cd tests && npm run test:all
python3 tools/check_versions.py
```

CI прогоняет то же самое: Python 3.8 / 3.11 / 3.13, Node 20 / 22.

## Правила, которые проверяет CI

1. **Зелёные тесты.** Любое изменение поведения расширения или сервера должно
   приходить с тестом в `tests/`.
2. **Версия в одном месте.** Источник правды — `extension/manifest.json`.
   Её обязаны повторять `extension/manifest.chrome.json`, `VERSION` в
   `server/server.py` и `CLIENT_INFO` в `server/mcp_client.py`.
3. **Заметки о релизе.** Для текущей версии обязан существовать
   `docs/releases/vX.Y.Z.md` (индекс — [`docs/releases/README.md`](docs/releases/README.md)).
4. **Никаких ссылок на старые архивы.** В документации используйте
   `terminal-bridge-<версия>-chrome.zip`, а не конкретный номер версии.
5. **`firefox-addon.xpi` в корне — артефакт сборки.** Не редактируйте его руками:
   он пересобирается из `extension/` командой `python3 tools/build_release.py`.

Всё перечисленное проверяет `python3 tools/check_versions.py` — запустите перед PR,
это быстрее, чем ждать CI.

## Стиль кода

- Отступы: 2 пробела в JS/JSON/CSS, 4 — в Python и PowerShell.
- Кодировка UTF-8, переводы строк LF (см. `.editorconfig`, `.gitattributes`).
- Комментарии — по-русски, по делу: объясняйте **почему** так, а не что делает строка.
  В проекте уже есть привычка ссылаться в комментарии на конкретный баг/версию — это полезно.
- В Python — только стандартная библиотека: `server.zip` должен запускаться
  без `pip install`.
- Ничего личного в репозиторий: `whitelist*.txt`, `server/mcp_servers.local.json`,
  `dist/`, `__pycache__` — в `.gitignore`.

## Коммиты и PR

- Один коммит — одна логическая правка. Сообщение в стиле
  `fix(panel): …`, `feat(mcp): …`, `docs: …`, `chore: …`.
- В описании PR: что было сломано, почему, как проверяли (какие тесты добавили).
- Скриншоты интерфейса (`docs/screenshots/`) обновляйте только осознанно:
  `node tools/generate_screenshots.js`.

## Безопасность

Модель угроз и принятые решения (включая политику `Origin: null`) описаны в
[`SECURITY.md`](SECURITY.md) — прочитайте перед правкой проверок доступа.
Коротко: сервер выполняет команды на машине пользователя, поэтому:

- Не ослабляйте проверки Host/Origin и токен без веской причины.
- Опасные команды должны оставаться в списке на подтверждение
  (см. `DANGEROUS`-паттерны в `extension/` и `server/`).
- Не логируйте токены и содержимое буфера обмена.
- `LEGACY_TOKEN_FILE` в `server/server.py` — намеренная обратная совместимость
  (миграция со старого `~/.ai-execute-runner.token`); не удаляйте.
- Не возвращайте `Access-Control-Allow-Origin: null` и не убирайте требование
  `Content-Type: application/json` для браузерных POST: это защита от RCE из
  песочницы веб-страницы.
