# Безопасность TerminalBridge

TerminalBridge по замыслу выполняет команды на вашей машине. Это значит, что
любая ошибка в проверках доступа = выполнение произвольного кода. Поэтому
модель угроз здесь описана явно, а не «подразумевается».

## Модель угроз

| Кто | Что может | Чем ограничен |
|---|---|---|
| Веб-страница в браузере (в т.ч. вредоносная) | отправить запрос на `127.0.0.1:8765` | проверка `Host`, политика `Origin`, CORS, требование JSON-тела, токен |
| Песочница веб-страницы (`<iframe sandbox>`, `data:`, `file:`) | то же, но с `Origin: null` | CORS-разрешение не выдаётся → ответ прочитать нельзя; `POST` без `application/json` отсекается |
| Другой пользователь ПК / процесс | прочитать `~/.terminal-bridge.token` | права файла `0o600`, домашний каталог |
| Внедрённая инструкция в чужом тексте (prompt injection) | заставить модель написать опасный `execute`-блок | детектор опасных команд, подтверждение, автопилот не запускает `hard`-команды, блокировка чтения секретов и загрузки файлов наружу |
| Локальный шелл | всё | вне модели: кто может запускать команды локально, тот и так имеет доступ |

Сервер слушает **только** `127.0.0.1` / `[::1]`, наружу не выставляется.

## Что проверяется на каждый запрос

1. **Host** — обязан быть локальным (`127.0.0.1`, `localhost`, `[::1]`, `::1`).
   Это защита от DNS-rebinding: чужой домен, указывающий на 127.0.0.1, отсекается.
2. **Origin**:
   - `chrome-extension://…` / `moz-extension://…` — разрешены (можно сузить флагом `--allowed-origin`);
   - `http(s)://127.0.0.1…` и `http://localhost…` — разрешены, кроме `/ax-token`;
   - отсутствует — разрешён (curl, нативные клиенты); CORS-заголовок не выдаётся;
   - `null` — разрешён, но **без** `Access-Control-Allow-Origin` (см. ниже);
   - всё остальное — `403`.
3. **`Content-Type: application/json`** — обязателен, если запрос пришёл из
   браузера (есть заголовок `Origin`). Иначе `415`.
4. **Токен** `X-Auth-Token` — обязателен для `POST /run`, `/abort` и `/mcp/*`
   (кроме `/ping` и `/ax-token`). Сравнение через `hmac.compare_digest`.
5. **Rate limit** (опционально, `--rate-limit`) и **whitelist** (опционально,
   `--whitelist`).
6. **Детектор опасных команд** в расширении: `hard`-команды требуют
   подтверждения даже при включённом автопилоте.

## Почему `Origin: null` разрешён, но без CORS

`Origin: null` присылают два совершенно разных клиента:

- **Service Worker расширения** (Chrome MV3) — легитимный локальный вызов.
  Если его отклонить, расширение уходит в статус offline; ровно это и починили
  в v2.12.5.
- **Песочница любой веб-страницы** — `<iframe sandbox="allow-scripts">`,
  `data:`-URI, `file:`. Для неё это способ дотянуться до localhost.

Различить их по одному заголовку нельзя, поэтому решение такое:

- запрос **не отклоняем** (иначе ломается расширение);
- **не отдаём** `Access-Control-Allow-Origin: null`. Без этого заголовка браузер
  не показывает тело ответа чужому origin'у, значит `/ax-token` из песочницы
  прочитать невозможно — а без токена `/run` бесполезен;
- **требуем** `Content-Type: application/json` от браузерных запросов. Простой
  `no-cors` POST (text/plain, urlencoded, multipart) отсекается, а JSON-запрос
  требует preflight, который из веба не проходит.

Расширению CORS не нужен вовсе: `fetch` из Service Worker с `host_permissions`
на `127.0.0.1` выполняется в обход CORS.

> ⚠️ Не «оптимизируйте» это, возвращая `Access-Control-Allow-Origin: null`.
> Такой заголовок означает «любая песочница в интернете может читать ответы
> сервера», то есть утечку токена и выполнение команд на ПК. Это и была
> реальная уязвимость до фикса.

## Секреты

- Файл токена `~/.terminal-bridge.token` создаётся с правами `0o600`, живёт
  вне репозитория и не пишется в логи.
- Путь к токену (и к legacy `~/.ai-execute-runner.token`) объявлен
  «сенситивным»: команда `view` его не отдаст.
- Детектор считает `hard`-командами чтение ключей (`id_rsa`, `id_ed25519`,
  `.aws/credentials`, `.git-credentials`, `.netrc`, `.gnupg`, `.kube/config`,
  токен моста) и отправку файлов наружу (`curl -d @`, `--data-binary @`,
  `-F file=@`, `-T`, `wget --post-file`, `Invoke-WebRequest -InFile`, `nc < file`).
  В автопилоте такие команды не выполняются без вашего подтверждения.

## Известные ограничения

- **`--no-token`** отключает авторизацию полностью. Полагаться в этом режиме
  остаётся только на проверки Host/Origin и CORS. Не используйте его на машине,
  где в браузере открываются посторонние сайты.
- **Whitelist по умолчанию** — это «удобный», а не «строго read-only» профиль:
  в нём есть `python`, `node`, `npm run`, `npm test`, потому что без них мост
  бесполезен для разработки. Интерпретатор и `npm run` выполняют произвольный
  код по определению — если нужен строгий режим, уберите их из `whitelist.txt`.
  Заведомо опасные конструкции (`find -exec/-delete`, `-c`/`-e`/`eval`,
  shell-метасимволы) блокируются всегда.
- **Селекторы чат-сайтов** живут в расширении и обновляются вместе с редизайнами
  ChatGPT/Claude/DeepSeek; это вопрос поддержки, а не безопасности.
- **MCP-инструменты** в whitelist-режиме заблокированы целиком: они выполняют
  код в обход shell-проверок.

## Как сообщить об уязвимости

Пожалуйста, **не** открывайте публичный issue с воспроизведением. Используйте
GitHub Security Advisory (вкладка *Security* → *Report a vulnerability*) или
личное сообщение автору репозитория. Опишите вектор, версии расширения и
сервера, и минимальный сценарий. Ответ — в течение недели.
